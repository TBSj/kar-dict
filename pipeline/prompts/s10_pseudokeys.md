# Инструкция: ключи OCR-выгрузки КБРС-1989, стоящие не на своём месте в алфавите

Словарь 1 — «Къарачай-малкъар-орус сёзлюк» (1989). Его OCR-выгрузка хранит статьи парами «ключ → текст» в порядке книги; разметка текста: `@…#` — полужирный (карачаево-балкарский), `$…%` — курсив (пометы), `~` — тильда = заглавное слово. Ключи-кандидаты ниже нарушают алфавитный порядок относительно ОБОИХ соседей. Причины бывают такие:

- `pseudo_tail` — **псевдоключ**: на стыке колонок/букв выгрузка начала новый ключ посреди чужой статьи; текст на деле — хвост ПРЕДЫДУЩЕЙ (иногда другой соседней) статьи. Пример: ключ `дери` с текстом «до мельчайших подробностей; @~ине дери тинтерге…» — хвост статьи «джик I» (с. 249).
- `garbled_key` — заглавное слово искажено распознаванием (статья настоящая, на своём месте в книге): `ахтларгъа` вместо `актларгъа` (актировать), `джкжлетиу` вместо `джюклетиу`, `хййырландырыргъа` вместо `хайырландырыргъа`, `ёнкелеу` вместо `ёпкелеу`.
- `split_word` — слово разрезано без дефиса: ключ `ур`, текст «у I 1) вор…» = статья **уру I** «вор».
- `ok` — ложная тревога: слово правильное, порядок нарушен из-за особенностей алфавита (например «нг» в заимствованиях: джунгли, конгресс, мангал), или запись — копия из продублированного блока выгрузки (у неё пустой `corpus_entries` и есть такая же запись с другим sid).

Вход: JSON-массив `[{sid, key, value, neighbours, kbrs_page_est, corpus_entries, known_pseudo}]`: `neighbours` — по 3 ключа до и после (sid, key, начало текста); `kbrs_page_est` — оценка страницы печатного словаря (±3); `corpus_entries` — статьи итогового корпуса, собранные из этого sid (word, def1, misc1 — как они выглядят сейчас); `known_pseudo=true` — псевдоключ уже подтверждён по скану ранее, нужно только найти владельца и разметить перенос.

Печатный словарь (скан без текстового слоя): `D:/Къагъыт/Къарачай/Китаб/Сёзлюкле/Карачаево-балкарско-русский словарь.pdf`. Смотреть страницу: `"D:/Projects/My_projects/Python/Py_projects/kar-dict/.venv/Scripts/python.exe" -I -X utf8 D:/Projects/My_projects/Python/Py_projects/kar-dict/pipeline/survey_tools/pdftool.py png "<pdf>" <страница> <out.png> 2.2 left|right` и открыть PNG. Колонтитулы страницы — первые буквы первой и последней статьи, по ним легко найти нужную страницу. Для `pseudo_tail` и спорных `garbled_key` сверяйся со сканом обязательно; для очевидных искажений (латиница, «кж» вместо «ю», «й» лишняя) достаточно соседей и знания языка.

## Что вернуть для каждой записи

- `verdict`: `pseudo_tail` | `garbled_key` | `split_word` | `ok`.
- для `pseudo_tail`: `owner_sid` — sid статьи-владельца (обычно предыдущий сосед; бери из `neighbours`), `owner_key`, `owner_headword` — печатное заглавное слово владельца (для раскрытия тильды), `tail_def1` и `tail_misc1` — текст хвоста, разложенный по правилам статьи: `def1` — русские значения (если хвост продолжает перевод), `misc1` — карачаево-балкарские примеры с переводами, пословицы и т. п.; тильду `~` раскрой заглавным словом ВЛАДЕЛЬЦА (с озвончением конечного согласного перед гласной, если у владельца есть помета вида (-ги)/(-гъы)), разметку `@#$%` сними.
- для `garbled_key` и `split_word`: `correct_headword` — правильное печатное заглавное слово (строчными, карачаевская орфография КБРС: дж, конечное -б, глаголы в инфинитиве на -ргъа/-рге; «кь/гь» → «къ/гъ»).
- `evidence` — чем подтверждено (страница скана, соседи, словообразование).
- `confidence`: `high` | `medium` | `low`.

## Формат результата

Запиши в указанный выходной файл JSON:
```json
{"items": [{"sid": 8024, "verdict": "pseudo_tail", "owner_sid": 8023, "owner_key": "джик", "owner_headword": "джик", "tail_def1": "", "tail_misc1": "…", "correct_headword": "", "evidence": "с. 249 лев.: …", "confidence": "high"}, …]}
```
Каждому входному `sid` — ровно одна запись, в том же порядке. UTF-8 без BOM.
